# 4.7.0 Priority Plan

Working theme: **Priority** (full note priority + a dedicated priority filter/sort/group control). Minor release on branch `4-7-0-priority`. Latest cut release: 4.6.1 "A Small World".

## Implementation status

`4.7.0.2` is open and implemented. Priority is available once in every note-editor header, Condensed supports direct priority updates, the unified Notes Priority popover uses one stable row of cycling SVG controls, legacy Priority sort settings migrate safely, square Priority headings cover both Notes lists, and exports retain Priority. Parse, desktop, repeated-open sizing, direct-update, and 375px smoke tests pass on port 8018; the line remains active for user review before `prep`.

## Goal

1. **Full priority support on ALL notes** — priority becomes a first-class field every note can carry and edit, not just Waypoint-pack notes. It shows consistently across all four note views and is included in exports.
2. **Better priority filtering + sorting** — one new Notes-header control that filters by priority, toggles ascending/descending priority sort, and groups notes by priority.
3. **Icon** — replace the "circle flag" on the priority control with a new `__CIRCLE_BADGE_MINUS`.

## Current state (what exists today)

- `priority` is already a persisted note field: `"1"`–`"5"` or `""`, normalized in `normalizeNotePriority` (≈3244) and repaired in `normalizeState` (≈3435). **No schema change needed for the field itself.**
- Editing today: the editor's priority `<select id="notePriority">` lives inside `#noteSetSection` (`index.html` ≈587), which is `class="note-set-section hidden"` and only surfaces for Waypoint-pack notes. Detailed cards (4.6.0) already expose per-note priority buttons via `waypointPriorityButtons(...)` for every note. → Gap: the regular editor doesn't let you set priority on a plain note.
- Sort: `notesSortMode` ∈ `alpha|chrono|priority` (runtime var ≈2511 + `state.settings.notesSortMode`). Three segmented buttons `#notesSortAlphaBtn/#notesSortChronoBtn/#notesSortPriorityBtn` (`index.html` ≈278-280). Priority sort uses `notePrioritySortRank` (unprioritized → rank 99) in `sortedNotesFor` (≈9046) and `sortPriorityForState`/`sortedMarkedStateAbbrs` (≈9020-9044).
- The "circle flag" is the Priority **sort** button's icon: `setButtonLabel("#notesSortPriorityBtn", __FLAG_CIRCLE, "Priority")` (≈5639).
- Filters present (no priority filter yet): level (`noteLevelFilters`), visit-type/icon, Show-Excluded (`notesHideExcludedOnly`), date precision (`notesDatePrecisionFilter`), coordinate (`notesCoordinateFilter`), search. State-level matchers: `stateMatches{LevelFilter,VisitTypeFilter,ExcludedVisibility,DatePrecisionFilter,CoordinateFilter}`; note pipeline: `notesForDisplay`/`filteredNotesFor` (≈8770-8778).
- Exports (Markdown/RTF/Text) do **not** currently include note priority (grep found none).
- `__CIRCLE_BADGE_MINUS` does **not** exist in `assets/js/icons.js` (only `__CIRCLE_BADGE_PLUS`). The user supplied the exact SVG to add (see Icon section).

## Decisions (from the user)

- **Priority control = one new button** placed **to the right of the sort toggle group, before the grouping (Category) button** in the Notes header. It opens a **popup** that does three things:
  1. **Filter** (default: off / no filtering): pick **exact priority**, **N or higher**, or **N or lower** (N = 1–5).
  2. **Sort**: **ascending / descending** toggle for priority sort.
  3. **Group by priority** toggle.
- The button's **icon/status reflects the active selection** (e.g. shows the active filter value / an active state when any priority option is engaged).
- The new button carries the new **`__CIRCLE_BADGE_MINUS`** icon. The standalone Priority **sort** toggle is **removed** (confirmed): the sort segmented control becomes **Alphabetical | Chronological** only, and priority sorting/grouping is driven from the new button.
- **Sort model (confirmed):** `notesSortMode` keeps only `alpha`/`chrono` and stays the **tiebreaker** (and the base sort when priority ordering is off). When the new button engages priority ordering, priority is the **primary** key (direction from the asc/desc toggle) and notes with equal priority fall back to the alpha-vs-chrono toggle. The existing **sort-cycle shortcut stays as-is — it's the Right Arrow** (`data-shortcut="→"` on the sort buttons), now cycling just Alphabetical ↔ Chronological.
- **Precedence (confirmed):** priority grouping supersedes the Category grouping toggle while active.
- **Condensed view (confirmed):** leave it clean — no priority badge there.

## Behavior / UX

### Priority on every note
- Promote a priority control into the **main note editor** for all notes (not gated by `#noteSetSection`). Keep the pack-note priority/"Add to active pack" controls working; the standalone priority field should be available regardless of pack linkage. Decide placement (e.g. near the Visit Level / tags) so it reads as a core field.
- Keep the existing per-card priority controls in Detailed view; ensure Expanded/Condensed show the priority badge consistently (Condensed intentionally omits the badge per 4.6.0 — confirm whether that should change now that priority is "full"; default: leave Condensed clean).
- Include priority in **exports**: Markdown, RTF, Plain Text, and confirm JSON already round-trips it (it does — it's a normal field). Add a compact "Priority: N" to per-note export lines.

### New Priority button + popup (filter / sort / group)
- **State (new `settings`)**, all defaulting to "off/none" so nothing changes for existing users:
  - `notesPriorityFilter`: `{ mode: "none" | "exact" | "gte" | "lte", value: 1-5 }` (default `mode:"none"`).
  - `notesPrioritySort`: `"none"` (default) | `"desc"` (high→low) | `"asc"` (low→high) — whether priority is the **primary** sort and its direction.
  - `notesPriorityGroup`: `false` default — render priority headings (implies priority ordering; uses `notesPrioritySort` direction, defaulting to `desc` if `none`).
  - Add defaults in `defaultState()` and repair/clamp in `normalizeState()`.
  - **Migration:** drop `"priority"` from the allowed `notesSortMode` values; in `normalizeState`, map a legacy `notesSortMode === "priority"` to `notesSortMode = "chrono"` **and** `notesPrioritySort = "desc"` so existing "sorted by priority" users keep that behavior. Right-arrow cycle / `cycleNotesSortMode` now toggles `alpha ↔ chrono` only.
- **Filter** applies in the notes pipeline: add a `noteMatchesPriorityFilter(note)` and a `stateMatchesPriorityFilter(abbr)` (state shows if any visible note matches), wired into `filteredNotesFor`/`notesForDisplay` and `sortedMarkedStateAbbrs` alongside the existing matchers. Unprioritized notes match only when `mode:"none"`.
- **Sort**: when `notesPrioritySort !== "none"` (or grouping is on), priority is the **primary** key in the chosen direction; **equal-priority notes are tiebroken by the alpha-vs-chrono toggle** (`notesSortMode`), then by the existing date/summary fallbacks. When priority sort is off, ordering is exactly today's `notesSortMode` (alpha/chrono). Update `sortedNotesFor`, `notePrioritySortRank`/`sortPriorityForState`, and `sortedMarkedStateAbbrs` to layer priority on top of the alpha/chrono comparator rather than replacing it. The **Right-Arrow sort cycle stays as-is**, now cycling alpha ↔ chrono; do not route priority through `notesSortMode`.
- **Group by priority**: when on, render notes (and locations) under "Priority 5 … 1" + "Unprioritized" headings (reuse the category-grouping/`renderNotesPanel` heading machinery; heading order follows the asc/desc direction; within a heading, alpha/chrono order). **Priority grouping supersedes the Category grouping toggle while active** (confirmed).
- **Button affordance**: icon `__CIRCLE_BADGE_MINUS`; show an active/badged state when a filter is set or grouping/non-default sort is on, with a tooltip describing the active selection. Popup pattern can mirror existing header pop-ups (e.g. the ring-style or map-label menus) for consistency and outside-click close.

## Resolved decisions

- Standalone priority sort toggle: **removed** (absorbed into the new button); sort group = Alphabetical | Chronological.
- Priority sort tiebreaker: **the alpha-vs-chrono toggle**; `notesSortMode` stays alpha/chrono and the **Right-Arrow** cycle shortcut is unchanged.
- Group-by-priority **supersedes** the Category grouping toggle while active.
- Condensed view: **leave clean** (no priority badge).

## Remaining risks

- **Mobile**: the new popup must fit small screens — reuse the on-screen-clamping patterns from the ring-style / basecamp toolbar menus, and place the button so the header still wraps cleanly at 375px.
- **Migration**: legacy `notesSortMode === "priority"` must be remapped (see Settings) so no saved state lands on an invalid sort.
- **State coordination**: the new button's pressed/active styling and the alpha/chrono segmented control must visibly reflect that priority is layered on top (e.g. button shows active state + tooltip; segmented control still shows the active tiebreaker).

- Filter exact/≥/≤ hides/show the right notes and updates the button status; sort asc/desc reorders; group-by-priority renders headings.
